# SEO关键词研究｜项目记忆

> 用途：以后用户说“SEO关键词研究”“按关键词库写内容”“用M01/M02生成文章”时，先读取本文件，再开始内容任务。本文记录的是已经确认过的方法和边界，不替代实时的 Ahrefs、Semrush 或 Google 数据。

## 1. 这项工作的真正目标

SEO不是单纯“写一篇文章”，也不是为了修改产品功能。完整链路是：

**用户搜索 → Google展示搜索结果（SERP）→ 判断搜索意图和页面类型 → 在合适的平台发布真正有用的内容 → 获得排名、点击、引荐流量或注册。**

SEO对象可以是官网页面，也可以是 Reddit 帖子、Medium文章、Dev.to文章、GitHub文档、YouTube页面等。用户负责手动找词和整理数据，AI从“内容任务书”开始负责写作、改稿、配图位置和发布前检查。

## 2. 关键词研究的人工流程（节省额度）

1. 先确定业务主题，例如 AI video generator、AI UGC ad generator、video meme generator、AI marketing video。
2. 在 Ahrefs 或 Semrush 用一个种子词找变体、问题词和长尾词；不要直接反复查询整个 reddit.com，这类查询很耗额度。
3. 记录关键词的搜索量（Volume）、关键词难度（KD）、搜索意图、SERP里出现的平台和排名靠前的URL。
4. 打开 Google 看真实SERP：结果是官网功能页、测评文章、教程、论坛讨论、视频还是目录页。
5. 只保留同时满足“和Wizstar相关、搜索意图能回答、竞争暂时可承受、能在目标平台发布”的词。
6. 同一需求的不同说法可作为变体词，但不能因为词不同就机械复制内容；一篇内容应围绕一个主词并自然覆盖相关变体。

### 关键词库建议字段

| 字段 | 填写内容 |
|---|---|
| Keyword ID | 使用 M01、M02 这类编号，不使用已被占用的 001 |
| Keyword | 原始英文关键词 |
| Search intent | Informational / Commercial / Transactional / Navigational |
| Volume | 工具显示的月搜索量；注明国家和日期 |
| KD | 工具显示的难度；注明来源和日期 |
| SERP platforms | Google结果里出现的 Reddit、Medium、官网、YouTube等 |
| SERP examples | 1–3个真实结果URL |
| Content angle | 要解决的问题或用户场景 |
| Target platform | Medium、Reddit、Dev.to等 |
| Wizstar fit | 能使用的已验证功能或素材 |
| Channel ID | 如 S_medium_01，用来归因来源，不代表关键词 |
| Status | idea / drafted / published / indexed / updated |

## 3. 如何判断一个词适不适合做

- **相关性**：用户搜这个词时，Wizstar能否自然解决问题；不相关的高流量词不要追。
- **意图匹配**：教程词写教程，体验/测评词写真实过程和结果，比较词写对比；不要拿产品广告去回答纯知识问题。
- **竞争可承受**：KD低只是起点，不等于一定能排名。还要看SERP前十的站点权威度、内容深度、发布时间和是否有论坛/个人文章。
- **平台匹配**：如果SERP里有大量社媒帖子，优先研究同平台的内容形式；如果几乎全是官网功能页，社媒帖子不一定能抢同一位置。
- **可验证价值**：必须能提供真实截图、视频、测试步骤、数据或经验，不能只改写别人的空泛结论。

“蓝海帖子”不是“点赞最多的帖子”，而是**有搜索流量或排名迹象、竞争相对可控、又和业务高度相关的内容机会**。原帖数据好只能说明它值得研究，不能保证仿写后也能排名。

## 4. Reddit / 社媒内容的做法

### 研究顺序

1. 用关键词在 Google 搜索：`site:reddit.com 关键词`，先找已经被Google收录的帖子。
2. 记录帖子标题、URL、社区、发布时间、点赞、评论、Google排名和帖子实际回答了什么。
3. 用 Ahrefs 只对少量候选URL做 Exact URL 检查；不要把整个 reddit.com 作为 Subdomains 查询。
4. 判断是“参与原讨论”还是“另写一篇新帖”。原讨论有空间就提供有用评论；问题已过时或没有合适位置，就写新的真实案例/教程。
5. 采用原平台认可的格式（讨论、问答、实测、教程、案例），但不复制标题、段落或虚构个人经历。

### 社媒SEO的现实边界

社媒帖子可以被Google收录并带来品牌曝光、引荐流量和部分SERP占位，但排名受平台权重、帖子互动、内容质量、发布时间和社区规则影响，不能保证结果。社媒工作重点是“回答用户问题并获得真实互动”，不是堆关键词或硬塞链接。

## 5. Medium的定位和链接规则

- Medium正文和个人主页外链通常会带 `rel="nofollow"` 或 `rel="ugc nofollow"`；每次仍应以页面源码或实际检查为准，不能承诺DoFollow。
- Medium的价值主要是内容分发、借平台权重争取SERP占位、引荐流量和品牌实体信号，不是直接给Wizstar传PageRank。
- 文章开头约70–110词直接回答搜索问题，再展开方法、证据和案例。
- 外链放在自然上下文中：例如“完整测试记录”“免费模板”“实际工作流”，不要堆精准商业锚文本。
- CTA可在痛点说明后和结尾各出现一次；一般每千字放1–2个外链即可。
- 如果主站已有同一文章，优先用Medium Import Story或设置Canonical URL，避免内容重复竞争；如果文章是Medium原生体验文，不要虚构Canonical。
- 外链必须带正确的渠道参数，例如：`https://wizstar.com/?channel_id=S_medium_01`。`channel_id`用于归因来源，不等于SEO关键词，也不能单独证明排名提升。

## 6. AI内容任务从哪里开始

用户人工完成关键词研究并把词放进表格后，AI从“生成内容任务书”开始。最少需要：

- Keyword ID和主关键词
- 目标平台
- 搜索意图和读者
- 内容形式（教程、案例、体验、比较等）
- 必须回答的问题
- 已验证的Wizstar事实和可用素材
- 目标标题方向、语气、篇幅
- 追踪URL / Channel ID
- 图片、视频需要放置的位置（如确有素材）

参考链接不是每次必填。只有在需要学习文章结构、验证事实或分析竞品内容时才使用；没有参考链接也可以依据任务书和已验证产品事实创作。

## 7. Wizstar已确认的可用事实（写作前优先引用）

截至2026-08-25，产品页确认的信息包括：

- AI Video Generator包含 **Reference to Video、Keyframe to Video、Text to Video** 三种模式。
- 三种模式均支持声音；Reference模式可加入图片、视频、音频等多模态素材，页面显示最多50个素材。
- Reference/Text模式可选4、10、15、20、25、30秒；分辨率480P/720P；画幅9:16或16:9；输出数量1–4。
- Keyframe模式需要首帧，尾帧可选；页面显示提示词上限2000字符。
- E-commerce Agent支持产品URL、商品图片和卖点；Creative Agent支持文字、图片、视频及风格/类型选择；两者可选择Seedance 2.5。
- “最多300秒”“10+语言”“最高4K”属于Agent工作流宣传口径，不应写成单次Seedance生成必然支持的参数。
- 不要在未验证时声称Wizstar有独立Seedance 2.5 API、某模式支持区域重绘、单次生成4K或固定credit价格。

## 8. Make自动化工作流的记忆边界

当时的设想是：**产品URL/素材 → 提取产品信息 → 生成脚本和视频Prompt → 调用Wizstar → 获取视频结果**。真正卡点是没有确认可用的公开Wizstar API或Webhook，因此不能把“浏览器里手动生成”描述成已完成的全自动调用。

可自动化的部分：表格读取、任务书生成、标题/正文/Prompt草稿、链接参数拼接、发布清单和结果记录。

需要真实API或人工操作的部分：登录、上传素材、选择模型、提交生成、下载视频、发布到第三方平台。除非用户提供并确认官方API文档，否则只写成“待API接入”或“人工执行”。

## 9. 发布后如何追踪

每条内容至少记录：发布URL、平台、发布日期、主关键词、Google是否收录、SERP位置、页面浏览/点赞/评论、外链点击、Wizstar访问、注册或激活。用 `channel_id` 区分来源；不要把平台本身的排名、官网的关键词排名和引荐流量混为一个指标。

## 10. 常见误区

- 低KD不等于低风险，也不等于发布后必定排名。
- 竞品官网排名好，不代表社媒仿写就能排名。
- “同平台发同类型”是匹配用户期待，不是复制原帖。
- 产品提交目录（AlternativeTo、G2、Capterra等）和内容发布（Medium、Reddit、Dev.to等）是两类任务，不要混用Skill。
- 目录收录、DoFollow属性、Google排名和真实转化都要逐项验证，不能从平台名称推断。
